# Задача для Codex — cinematic automotive hero (реализация, не концепт)

Ты работаешь в корне локального проекта автомобильного лендинга. Нужно **сейчас реализовать только первый экран и связанную с ним scroll-driven сцену** уровня премиального automotive digital experience (референс: Forge Automotive / Joe Ben Taylor, который пользователь показывал в Pinterest). Не копировать чужой сайт буквально; повторить уровень арт-дирекшена, композиции, чувства движения и переходов.

## 0. Сначала изучи проект и реальные ассеты

1. Посмотри структуру директории, package.json, существующий стек и конфиги. Не сноси существующий работающий код без необходимости.
2. **В корне проекта лежит видео, сгенерированное для hero.** Найди `.mp4`/`.mov`/`.webm` в корне (если несколько — проанализируй все и выбери подходящий). Изучи фактическую длительность, размеры, кодек, соотношение сторон и содержимое (через ffprobe/ffmpeg, если доступны; просмотри кадры в начале, середине и конце). Не придумывай имя видео.
3. Смысл видео: в тёмном студийном окружении три BMW, в центре яркая красная BMW, по краям тёмные BMW; камера направляется к центральной машине и через лобовое стекло оказывается перед её салоном. Последний кадр — мрачные спортивные сиденья с красной подсветкой, вид снаружи через лобовое. **Используй именно приложенный видеофайл**, не заменяй его случайной стоковой машиной или CSS-имитацией.
4. Если файла нет, не блокируй проект: создай явный конфиг пути и аккуратный fallback-постер, а в отчёте укажи, куда положить видео. Если файла нет, не говори, что видел его.
5. Извлеки из реального ролика постер первого кадра и, по возможности, постер последнего кадра. Исходник сохрани; рабочие ассеты положи в `public/media/hero/` (или эквивалент существующего стека).

## 1. Стек и качество реализации

Если проект ещё пустой, стартуй с **Vite + React + TypeScript**, **GSAP + ScrollTrigger + @gsap/react**, **Tailwind CSS** для интерфейса (можно сочетать с CSS Modules/обычным CSS для сложной художественной вёрстки). Если проект уже использует адекватный React/Next/Astro стек — интегрируй в него, не переписывай ради выбора инструмента.

Не нужно Three.js, react-three-fiber, тяжёлых 3D-библиотек: 3D-пролёт уже запечён в видео. Не нужны UI-киты с типовыми карточками. Lenis — только если реально улучшает поведение и не ломает мобильный скролл; по умолчанию можно оставить нативную прокрутку + GSAP scrub.

Архитектура: отделить `IntroPreloader`, `HeroExperience`, `HeroVideo`, `HeroTypography`, `FinalHeroStatement` и логику `useScrollVideo` (или аналог). Текст, лого и ссылки держать в легко редактируемом конфиге. Избегать глобальных магических селекторов и утечек GSAP — использовать `useGSAP` со scope и корректным cleanup.

## 2. Главная художественная идея

Премиальный, дерзкий, тёмный автомобильный editorial с атмосферой BMW M, ночного гаража и авторской автомобильной рекламы. Чёрный `#020202`, почти белый текст, минимальный холодный серый. Красный уже есть в самом видео, не добавляй агрессивный красный в UI. Никакого золота, градиентных CTA в стиле шаблонного авто-салона, стекломорфных карточек, дешёвых неоновых свечений, случайных иконок.

Вдохновение: строгая сетка, огромная выразительная контрастная типографика, композиция с тремя автомобилями, очень деликатные линии и микродетали, много воздуха. Финальный результат должен выглядеть как живой арт-дирекшен профессиональной студии, а не очередной React template.

Типографика: выразительный качественный editorial serif для большой фразы (кириллица ОБЯЗАТЕЛЬНО поддерживается шрифтом; подбери подходящий), чистый современный grotesk/sans для интерфейса. Используй настоящие шрифты с корректной лицензией и нужными glyphs, а не системную Times New Roman. Минимум 2 типографических уровня: большой артистичный заголовок и микро-текст с letter-spacing.

Не размещай заголовки поверх лицевой части красной BMW так, чтобы пропали капот, решётка и фары. Учитывай фактическую композицию первого кадра.

Временное редактируемое название, если в проекте ещё нет бренда: `NOIR AUTO`. Не создавать логотип-картинку без запроса; сделай аккуратный текстовый wordmark или простую SVG-монограмму, которую позже можно заменить. Не выдумывай фактов, отзывов, цифр продаж, цен, контактов, сертификатов.

## 3. Точный пользовательский сценарий

### A. Intro / экран загрузки (до скролла)
- Сразу после открытия — полностью чёрный экран (`#000`). Никакого flash белого HTML, никакого появляющегося по кускам интерфейса.
- Через короткую паузу в центре медленно проявляется лаконичное лого/wordmark, можно с лёгким blur-to-sharp, без вращений или bounce.
- Лого слегка держится, затем плавно растворяется в чёрном.
- После него из того же чёрного плавно проявляется **первый, неподвижный кадр нашего видео**.
- С небольшим художественным отставанием отдельными stagger-анимациями проявляются headline, микротекст, навигация, CTA и scroll indicator. Пользователь получает кадр, который хочется рассмотреть. НЕ запускать видео как автовоспроизведение.
- Длительность интро ориентировочно 1.8–2.8 сек при нормальной загрузке; не задерживать пользователя искусственно на 6–8 секунд. Переход основан на готовности постера/метаданных, имеет таймаут и graceful fallback. Если видео не загрузилось — показать постер и работоспособный hero; никакой бесконечной заставки.
- Во время интро ограничить скролл без прыжков вёрстки, после — восстановить. Интро по умолчанию один раз за вкладку/сессию; повторные переходы не должны снова заставлять смотреть заставку. Уважать `prefers-reduced-motion`.

### B. Первый кадр / hero composition
- Экран на всю ширину и высоту окна (`100svh`/`100dvh` с продуманной поддержкой мобильных браузеров), тёмный фон. В центральной плоскости — три BMW из первого кадра.
- Видеосцена имеет лёгкое затемнение ВВЕРХУ и ВНИЗУ, плавно смешивается с абсолютно чёрным фоном. Достичь плавного стыка CSS-градиентами с учётом уже затемнённых краёв видео; не затемнять машины до нечитаемости.
- Минималистичный header на прозрачном фоне, интегрирован в композицию: небольшое лого слева, «КАТАЛОГ» / «КОНТАКТЫ» или один компактный пункт справа; тонкие разделители там, где они уместны. На мобильном не пытаться уместить десктопное меню.
- Большой центральный editorial заголовок (пример, можно доработать копирайтинг: **«МАШИНЫ С ХАРАКТЕРОМ.»**) в верхней свободной зоне кадра, максимум 2 строки. Деликатный подзаголовок: «Подбор автомобилей для тех, кто выбирает своё» (можно изменить, но не придумывать юридических обещаний).
- Внизу аккуратный scroll-indicator `ЛИСТАЙТЕ ВНИЗ`, тонкая вертикальная линия/прогресс; одна ясная CTA «СМОТРЕТЬ АВТО». Кнопка должна работать (скролл к следующему блоку), не декоративная.
- Маленький нюанс: UI должен выглядеть элегантно даже если загружен только первый кадр, до готовности видео.

### C. Скролл превращается в камеру
**ЭТО ОСНОВНАЯ ФУНКЦИЯ**. После intro пользователь начинает обычный вертикальный скролл. Hero остаётся на месте с помощью `ScrollTrigger pin`; прокрутка управляет временем видео (`video.currentTime`) от первого до последнего кадра. Скролл вверх — движение назад. Не запускать ролик через `.play()` как обычную анимацию. Прокрутка должна быть плавной и обратимой.

Пример storyboard по нормализованному прогрессу scroll-секции, допускается улучшить пропорции после просмотра видео:
- `0.00–0.12`: герой статичен, текст виден; лёгкое движение только деталей UI.
- `0.12–0.24`: заголовок, подзаголовок, CTA, scroll indicator плавно исчезают (opacity + маленький y/blur), header становится почти незаметным. БЕЗ больших прыжков/кручения букв.
- `0.20–0.78`: прогресс скролла последовательно перематывает видео `0 → duration`. Кадр действительно меняется от скролла, а не от времени. На экране почти нет UI, зритель смотрит на пролёт к красной BMW и внутрь салона.
- `0.76–0.90`: на последних кадрах затемняющий чёрный слой постепенно усиливается; силуэты сидений/красные линии видны в начале затемнения, в конце — чистый `#000`.
- `0.87–0.97`: на чёрном фоне выразительно, последовательно появляются финальная типографика, подзаголовок и CTA.
- `0.97–1.00`: финальный контент полностью видим, герой удерживается ещё немного, затем естественно отпускается pin и переходит в следующую секцию без скачка.

Считать проценты рабочей режиссурой, а не догмой. Видео может быть длиннее/короче 8 секунд — брать реальную `duration`. Важно: не делать заметную паузу или пустой чёрный экран на границе. Не останавливать видео при прокрутке вперёд прежде чем реально дошли до финального кадра. При обратном скролле всё воспроизводится логично в обратном порядке.

### D. Финальный чёрный кадр / информационный экран
- Фон совершенно чёрный, можно оставить едва заметный шум/текстуру если это не ухудшает читаемость и производительность.
- Новый большой заголовок (первоначальный вариант): **«ТВОЙ ХАРАКТЕР. ТВОЙ АВТОМОБИЛЬ.»**; на десктопе сильная editorial-композиция с большим заголовком и маленьким сопровождающим текстом, на мобильном аккуратный вертикальный стек.
- Небольшой текст, например: «Подбор, который начинается с твоих предпочтений.» Не добавлять фальшивые цифры, награды, гарантии и географию, которых нет в задаче.
- CTA «ПЕРЕЙТИ К КАТАЛОГУ» ведёт к реальному якорю следующего блока (если его пока нет — сделать чистую минимальную секцию-якорь без имитации готового каталога).
- Заключительное появление должно ощущаться эмоциональной точкой видео, а не обычной всплывающей карточкой.

## 4. Видео, производительность и mobile Safari — обязательные условия

- Проверить источник с `ffprobe` (если доступен); не слепо копировать гигантский исходник в продакшен.
- Подготовить оптимизированный H.264 MP4 (`yuv420p`, `+faststart`), по возможности версии для desktop и mobile. Нужен хороший seek: обоснованно подобрать интервал ключевых кадров; проверить плавность перемотки в реальном браузере. Предусмотреть poster первого и последнего кадров. Не перекодировать без необходимости, если исходник уже подходит.
- Использовать `<video muted playsInline preload="auto" ...>` без звука и без controls; не ставить `autoplay`, если скролл управляет видео. Учитывать загрузку metadata/seeked и возможность программного seek в Safari.
- Привязка видео к скроллу должна избегать бесконечных перезаписей `currentTime` и seek-очередей. Реализовать rAF/оптимизацию seek и проверять события `loadedmetadata`, `canplay`, `seeked`, `error`; корректная синхронизация с GSAP. Не хранить текущую позицию видео в React state на каждый тик.
- Важно: HTML5 video scrubbing по `currentTime` на iOS может быть менее плавным, чем на desktop. Если тесты показывают фризы, применить устойчивую альтернативу: оптимизированную WebP/AVIF sequence из реального видео, отрисованную через `<canvas>` или `<img>` со сменой кадров по scroll progress, с ограничением памяти и ленивой загрузкой. Это fallback, а не повод сразу слепо создавать сотни тяжёлых кадров.
- На смартфонах НЕ обрезать сцену так, чтобы центральная машина исчезла. Для 16:9 ролика внутри вертикального экрана допустима cinematic letterbox-композиция: чёрный фон, видео по центру, сильные мягкие верхний/нижний градиенты и UI в свободных зонах. Выбери решение по фактическим кадрам. `object-fit: cover` на все устройства без проверки — ошибка.
- `prefers-reduced-motion`: минимальная заставка/без неё, статичный первый постер, понятный контент и возможность перейти к финальному CTA; не навязывать длинный pinned-scroll. Для медленного соединения или неработающего видео — poster fallback.
- Не перекрывать UI вырезами экрана; учитывать `env(safe-area-inset-*)`, изменение адресной строки и resize/ориентации; desktop 1440×900 / 1920×1080, iPhone 375×667 / 390×844 / 430×932.
- Интро и эффект должны быть приятными, без лагов и заметного скачка layout, без горизонтального скролла, с доступными кнопками и достаточным контрастом.

## 5. Результат, который требуется от тебя как разработчика

**Не ограничивайся объяснением или макетом — непосредственно создай файлы и реализуй работающий экран.**

1. Самостоятельно исследуй текущий проект и видео, затем внеси изменения.
2. Сверстай и анимируй preload → hero first frame → UI enter → UI exit → scroll-controlled video → fade to black → new statement → seamless handoff.
3. Подготовь корректные production assets и пути к ним, не коммить многогигабайтный оригинал без необходимости.
4. Добавь минимальный следующий якорь/блок, только чтобы проверить финальный переход, **не делай пока весь лендинг, каталог и админку**.
5. Запусти проект локально, проверь сборку и ошибки в консоли. При наличии браузера открой реальную страницу, проверь видимые кадры и переходы, поправь несовершенства. Проверь mobile viewport и обратную прокрутку. Если не можешь проверить мобильный Safari, не заявляй, что проверил.
6. Оставь краткое README: где видео, где менять логотип/тексты, как запускать, что сделано, что осталось и какие есть ограничения по iOS.
7. В финале дай честный отчёт по изменённым файлам, командам и тестам, а также что нужно от пользователя, если чего-то не хватило.

### Критерии готовности

- На старте полностью чёрный экран, логотип появляется и исчезает, затем плавно проявляется неподвижный первый кадр BMW.
- Текст и элементы управления появляются ПОСЛЕ видео, а не одновременно с ним.
- При скролле заголовок исчезает, **видеоряд управляется колесом мыши/свайпом**, двигается вперёд и назад, не autoplay.
- При приближении к концу ролика салон постепенно проваливается в чёрный; появляется новый большой текст и кнопка.
- Вёрстка выглядит дорого и чисто, без шаблонных деталей. На телефоне главный автомобиль хорошо виден.
- Ни одна секция не дёргается, видео не превращается в чёрный прямоугольник при seek, ничего не висит на loader.
- Все кнопки работают, нет ошибок компиляции/консоли, корректно обрабатываются reduced motion и отсутствие видео.

Приоритет: визуальная выразительность → корректный скролл-видеопереход → мобильная надёжность → остальные украшения. Не уходи в дополнительные секции. Твоя задача — **практически идеальный cinematic hero**, который уже можно показывать как самостоятельный работающий демо-экран потенциальным клиентам.
